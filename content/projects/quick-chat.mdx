## Overview

QuickChat is a high-performance messaging platform designed to explore large-scale realtime communication architectures. It emphasizes horizontal scalability and a resilient offline-first user experience.

Key focus areas:
- Horizontal WebSocket scaling
- Local-first state management
- 60 FPS UI performance
- Event-driven consistency

## Performance Engineering

Connection resilience and hot-path efficiency shipped in 7 rollback-safe phases — every reconnect resyncs, every send is timed, every broadcast is scoped.

<FeatureGrid>
  <FeatureCard 
    title="Infinite Reconnect" 
    description="Reconnect attempts capped at 5 meant a dead socket until reload. Now unbounded with 500ms→10s exponential backoff + jitter — subway rides included."
    icon={Share2}
  />
  <FeatureCard 
    title="Room Re-join on Connect" 
    description="Server-side rooms die with the socket, so read receipts silently froze after blips. conversation:join re-fires on every connect."
    icon={MessageSquare}
  />
  <FeatureCard 
    title="Send-Path Instrumentation" 
    description="Server stamps receivedAt on every ack; client keeps a 200-sample RTT ring with p50/p95 and sent/acked/failed counters. Latency claims are measured, not estimated."
    icon={Activity}
  />
  <FeatureCard 
    title="Presence Dedup" 
    description="user:online/offline broadcast to every socket on every tab connect. Now emitted only on first/last socket per user — multi-tab flapping gone."
    icon={Server}
  />
  <FeatureCard 
    title="Auth Handshake Cache" 
    description="Every (re)connect hit Mongo for the user record. Cache-aside snapshot in Redis (15m TTL) turns reconnect storms into cache hits."
    icon={Database}
  />
  <FeatureCard 
    title="Pipelined Heartbeat" 
    description="Presence refresh was one Redis RTT per connected user every 30s. Now a single pipeline round trip for all of them."
    icon={Server}
  />
  <FeatureCard 
    title="Keyset Catch-up" 
    description="Reconnects ask for everything since the newest stored timestamp — no offsets, so concurrent inserts can't shift windows. Merged via idempotent bulkPut."
    icon={CheckCircle2}
  />
  <FeatureCard 
    title="Batched Ingest + Quiet Logs" 
    description="Bursts buffered (500-cap, drop-oldest) and flushed per macrotask in one Dexie transaction. Per-message logs demoted to debug; console output dev-only."
    icon={Layout}
  />
</FeatureGrid>

## Technical Challenges

<ChallengeCard
  title="Scaling WebSockets"
  problem="A single Node.js instance limits concurrent connections, preventing the system from scaling horizontally."
  solution="Implemented Redis Pub/Sub as a message broker to synchronize state across multiple Socket.io server instances."
  result="Seamless message delivery across distributed servers supporting 10k+ concurrent users."
/>

<ChallengeCard
  title="High-Performance Rendering"
  problem="Rendering large chat histories caused DOM bloat, layout thrashing, and laggy scrolling."
  solution="Adopted window virtualization and leveraged CSS overflow-anchor to maintain scroll position during updates."
  result="Maintained 60 FPS scrolling performance with 10,000+ messages in the view."
/>

<ChallengeCard
  title="Resilient Connectivity"
  problem="Unstable network conditions caused message loss and a broken user experience."
  solution="Designed a local-first architecture using Dexie.js. Messages are persisted locally first and synced via an idempotent retry queue."
  result="100% message delivery reliability even in intermittent connectivity environments."
/>

## Lessons Learned

*   **Distributed Systems:** Designing pub/sub patterns across multiple server instances.
*   **Offline State:** Managing complex reconciliation between local and server databases.
*   **Browser Optimization:** Mastering virtualization and layout stabilization for high-volume UIs.
*   **Scalability:** Implementing horizontal scaling strategies for persistent connections.
*   **Measure first:** Latency numbers without instrumentation are hopes — the RTT ring made every later optimization rankable.
*   **Bound the buffers:** An unbounded queue and a global broadcast are the same bug at different scales.
